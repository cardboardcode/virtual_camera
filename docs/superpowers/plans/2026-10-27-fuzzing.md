# Minimalistic Fuzzing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a minimal, CI-runnable libFuzzer setup that fuzzes `ImageViewer::decode_image` — the package's untrusted network boundary — and prove it finds at least one real defect.

**Architecture:** Standard `cargo-fuzz` layout: a separate `fuzz/` crate (own lockfile, nightly/libFuzzer) that path-depends on the root crate. One fuzz target feeds generated `sensor_msgs::Image` structs into `decode_image` and asserts the call returns `Ok` or `Err` (never panics/UBs). A seed corpus generated from the shipped JPEG plus hand-crafted edge-case messages gives the fuzzer a foothold. A GitHub Actions workflow (`.github/workflows/fuzz.yaml`) runs it as automated CI on every push/PR, inside the existing Docker image, uploading artifacts only on failure.

**Tech Stack:** Rust 2021 + nightly (libFuzzer), `cargo-fuzz`, `libfuzzer-sys`, existing `opencv` binding, existing Docker image `vcam_image:rolling`, GitHub Actions.

**Spec:** This plan is self-referential (no separate spec); the requirement is "minimalistic example of fuzzing practical for this ROS 2 package."

## Global Constraints

- Rust 2021 for the root crate; the `fuzz/` crate is independent (standard cargo-fuzz layout, own `Cargo.lock`).
- Apache 2.0 license header on every new `.rs` file; new bash scripts get `chmod +x` and the repo's comment-style header.
- All builds/runs verified inside Docker via `scripts/2_create_docker_container.bash` (the root crate's `generate_ros_types!` macro needs `/opt/ros/rolling` or a ROS-enabled host).
- CI runs the same in-Docker pattern: build image, install nightly + `cargo-fuzz` inside the container, time-box the fuzz run so a job cannot hang CI, upload fuzz artifacts as a job artifact when the run finds a crash.
- Commit style: gitmoji prefix + `git commit -s` (DCO sign-off).
- YAGNI: exactly **one** fuzz target, no custom runner script, no sanitizers-by-default wiring beyond libFuzzer's built-in ASan in `cargo fuzz`.

## Review Focus

Latent defects the fuzzer should be able to hit (each pinned by a seed corpus entry in Task 3, and all implicitly exercised by the target in Task 2):

1. `height`/`width` ≥ 2³¹ — `as i32` truncation yields negative dims passed to the unsafe `Mat::new_rows_cols_with_data`.
2. `data.len()` < `step * height` — buffer underrun (UB, ASan should catch).
3. `step = 0` with non-zero `height` — row-stride arithmetic degenerates.
4. Zero `width` or `height` with non-empty `data` — reshape against degenerate dims.
5. `encoding` strings outside the 7 supported set — must `Err`, never `Ok` with wrong channel count.

### Task 2: The `decode_image` fuzz target

**Files:**
- Create: `fuzz/fuzz_targets/decode_image.rs`
- Modify: `fuzz/Cargo.toml` (add the `[[bin]]` entry)

**Interfaces:**
- Consumes: `virtual_camera::viewer::ImageViewer::decode_image(&SensorImage) -> Result<Mat, Box<dyn Error + Send + Sync>>` (existing).
- Produces: executable fuzz target named `decode_image`. No root-crate changes in this task — if the fuzzer finds a defect, Task 3 fixes it.

- [ ] **Step 1: Register the target**

In `fuzz/Cargo.toml`, add:
```toml
[[bin]]
name = "decode_image"
path = "fuzz_targets/decode_image.rs"
```

- [ ] **Step 2: Write the target**

`fuzz/fuzz_targets/decode_image.rs` (Apache 2.0 header above). Behavior: parse the byte vector into a `sensor_msgs::Image` — u32 `width`, u32 `height`, u32 `step`, encoding chosen by hash over the 7 supported strings **plus** `"junk_encoding"`, and `data` as the remaining bytes — then call `ImageViewer::decode_image(&msg)`. No assertions on `Ok`/`Err` (either is legal); the invariants are *no panic, no abort, no ASan report*. Use `fuzz_target!`; guard the decode call so a panic is converted into a libFuzzer crash (it already is, via panic = abort in the fuzz build).

- [ ] **Step 3: Build**

Run: `cargo +nightly fuzz build`
Expected: `decode_image` target compiles.

- [ ] **Step 4: Run without seeds, short, and record baseline behavior**

Run: `cargo +nightly fuzz run decode_image -- -max_total_time=60`
Expected: runs; note whether a crash is already found (likely, given the Review Focus list). If a crash occurs, **save the reproducer** from `fuzz/corpus/decode_image/` (it lands under `fuzz/artifacts/decode_image/`) — Task 3 triages it.

### Task 3: Seed corpus + triage of the first hit

**Files:**
- Create: `fuzz/seed_corpus/decode_image/` (directory with seed messages)
- Create: `fuzz/generate_seeds.rs` (a plain Rust integration-test-style binary OR inline `#[test]`; simplest: a `#[test] fn gen_seed()` in Task 2's file gated by an env var — instead: add `fuzz/seeds.rs` as a bin)
- Modify: `src/viewer.rs` (fixes found in triage; minimal change only — see Step 3)
- Modify: `tests/viewer_tests.rs` (regression tests for the fix)

**Interfaces:**
- Consumes: `virtual_camera::mat_to_sensor_msgs_image(&Mat, &str)` to encode the shipped JPEG into a valid seed.
- Produces: `fuzz/seed_corpus/decode_image/` with 1 valid JPEG-derived message + 5 hand-crafted edge-case messages matching the five Review Focus lines; fixed `decode_image` with validation added.

- [ ] **Step 1: Write the seed generator**

`fuzz/seeds.rs` (`[[bin]] name = "seeds" path = "seeds.rs"` in `fuzz/Cargo.toml`): builds a `SensorImage` from `data/nadezhda_diskant.jpg` via `imgcodecs::imread` + `mat_to_sensor_msgs_image`, then serializes it to bytes in the same layout Task 2's target deserializes (u32 width ‖ u32 height ‖ u32 step ‖ encoding index u32 ‖ data). Write 6 files into `fuzz/seed_corpus/decode_image/`: one valid; one height = 0xFFFFFFFF; one `data` truncated to half; one `step = 0`; one `width = 0, data = [0u8; 16]`; one `encoding = "junk_encoding"` with valid dims.

- [ ] **Step 2: Generate**

Run: `cargo -q run --manifest-path fuzz/Cargo.toml --bin seeds` (note: the fuzz crate's non-fuzz bins build fine on stable)
Expected: 6 seed files exist under `fuzz/seed_corpus/decode_image/`.

- [ ] **Step 3: Triage the crash from Task 2 (or run again against seeds)**

Run: `cargo +nightly fuzz run decode_image -- -max_total_time=300`
If (as expected) it reports an out-of-bounds read in `Mat::new_rows_cols_with_data` / `reshape`: fix in `src/viewer.rs:decode_image` by adding **up front, before any OpenCV call**:
   - reject if `step == 0` or `width == 0` or `height == 0` → `Err(...)`;
   - reject if `height as u64 * step as u64` exceeds `2^40` (sane guard) or if `msg.data.len() as u64 < height as u64 * step as u64` → `Err("image data too short")`.
   This eliminates the i32 truncation and the underrun in one gate and is the minimal fix. Do not change the rest of `decode_image` in this task.

- [ ] **Step 4: Regression test for the fix**

In `tests/viewer_tests.rs`: construct a `SensorImage` matching each of Review Focus lines 1–5 (using the same fields) and assert `ImageViewer::decode_image(&msg).is_err()` for each, plus one valid case returning `Ok`.

- [ ] **Step 5: Run the full suite + fuzzer clean**

Run: `bash scripts/run_container_tests.bash`
Expected: all green.
Run: `cargo +nightly fuzz run decode_image -- -max_total_time=300`
Expected: no new crashes (existing corpus retained).

- [ ] **Step 6: Commit**

```bash
git add fuzz tests/viewer_tests.rs src/viewer.rs
git commit -s -m ":bug: validate SensorImage geometry before OpenCV decode"
```

### Task 4: GitHub Actions CI workflow + docs

**Files:**
- Create: `.github/workflows/fuzz.yaml`
- Modify: `README.md` (new "Fuzzing" section)

**Interfaces:**
- Consumes: Tasks 1–3 (the `fuzz/` crate, seeds, fixed `decode_image`).
- Produces: a `Fuzz` workflow triggered on every push to `main`/`rolling` and on PRs, that builds the image, time-boxes the fuzz run inside Docker, and uploads `fuzz/artifacts/` as a job artifact on failure.

- [ ] **Step 1: Write `.github/workflows/fuzz.yaml`**

Shape (adjust job names to taste, mirror `ci.yaml` conventions):

```yaml
name: Fuzz

on:
  push:
    branches: [main, rolling]
  pull_request:

jobs:
  fuzz:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build Docker image
        run: docker build -t vcam_image:rolling .

      - name: Run fuzz target (time-boxed)
        run: |
          set -e
          docker run --rm \
            -v "$GITHUB_WORKSPACE":/virtual_camera_ws/src/virtual_camera \
            -w /virtual_camera_ws/src/virtual_camera \
            vcam_image:rolling \
            bash -c '
              rustup toolchain install nightly --profile minimal
              cargo install cargo-fuzz --locked
              cargo +nightly fuzz run decode_image -- -max_total_time=120
            '

      - name: Upload fuzz artifacts (crashes)
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: fuzz-artifacts
          path: fuzz/artifacts/
          if-no-files-found: ignore
```

Notes: `-max_total_time=120` keeps CI bounded; `cargo fuzz run` exits non-zero on any crash, so the job fails and the upload step fires. No `--sanitizer` flag needed (ASan is on by default in `cargo fuzz`).
